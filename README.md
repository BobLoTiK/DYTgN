# net-suite

Один пульт для трёх сетевых штук, которые раньше жили сами по себе. Скачал один
`net-suite-setup.exe`, запустил — дальше всё по ярлыкам.

## Чем это является и чем нет

Это **не форк** zapret и **не форк** TgWsProxy. Код этих проектов здесь не менялся
и не пересобирался: в `bin\` лежат их оригинальные бинарники как есть, а вся
собственная часть репозитория — обвязка: запуск, проверки, восстановление после
падений, PAC-сервер, поиск рабочей ноды и установщик.

Если назвать это форком, получится неправда: форк — это изменённые исходники под
своим именем, а здесь чужой код только запускается. Поэтому правильная формулировка:
**оркестратор/пульт над сторонними утилитами**, каждая из которых принадлежит своим
авторам и распространяется под своей лицензией.

| компонент | что это | откуда | что делает |
|---|---|---|---|
| **zapret** (`winws.exe`) | обход DPI через WinDivert | github.com/bol-van/zapret, взят в готовой сборке `zapret-discord-youtube` | лечит Discord/YouTube, запускается своей службой `zapret` |
| **TgWsProxy** | MTProto → WebSocket мост | сторонняя утилита `TgWsProxy_windows.exe`, бинарник как есть | Telegram через локальный `127.0.0.1:1443` |
| **sing-box** | прокси-движок | github.com/SagerNet/sing-box | TUIC-туннель, socks `127.0.0.1:10808` |
| **Xray** | прокси-движок (фолбэк) | github.com/XTLS/Xray-core | VLESS-резерв, если TUIC-ноды мертвы |

Лицензии у всех разные и живут в их собственных репозиториях — этот репозиторий их
не перелицензирует и не перераспространяет как свои.

| модуль этого репо | где | что делает |
|---|---|---|
| `netsuite.ps1` | корень | вся логика: on / off / status / ensure / restart |
| PAC-сервер | `notion\pacsrv.ps1` | `http://127.0.0.1:10810/proxy.pac` — через туннель только домены Notion |
| ноды | `notion\build-tuic.ps1`, `build.ps1` | ищет и проверяет бесплатные ноды, пишет `sb-config.json` |
| установщик | `dist\net-suite-setup.exe` | клон репо в `%LOCALAPPDATA%\net-suite\app` + установка |

## Установка

Скачать `net-suite-setup.exe` из [релиза](https://github.com/BobLoTiK/DYTgN/releases/latest),
запустить, дождаться конца. Он клонирует репозиторий (~130 МБ, один раз), задаёт
четыре вопроса (Enter = да) и вызывает `setup.ps1`:

1. ярлыки на рабочем столе?
2. автозапуск при входе в Windows?
3. проверять туннель каждые 10 минут (задача планировщика)?
4. запустить всё сразу?

Ответ «нет» не только не создаёт, но и убирает уже существующее — так установщик
работает и как настройка. Повторный запуск = обновление (`git pull` + установка).

Либо вручную: скачать zip, распаковать, `install.bat` (без вопросов, всё по умолчанию).
Тонкая настройка — флаги `setup.ps1`: `-NoDesktop`, `-NoAutostart`, `-NoTask`, `-NoStart`,
`-SkipStart`.

## Что делает установка

1. Проверяет движки в `bin\` (sing-box, xray, TgWsProxy) и докачивает недостающие.
2. Если нет `notion\sb-config.json` — ищет рабочую бесплатную ноду (1–3 минуты).
3. Создаёт ярлыки на рабочем столе и запись в автозагрузке.
4. Ставит задачу проверки ноды раз в 10 минут.
5. Поднимает всё и показывает таблицу статуса.

Дальше нужен только рабочий стол: **«Сеть вкл»**, **«Сеть выкл»**, **«Сеть статус»**,
**«Notion»** — последний просто открывает Notion в Firefox.

## Как это работает с Firefox

У Firefox по умолчанию `network.proxy.type = 5` — «использовать системные настройки
прокси». Система читает `AutoConfigURL` из реестра, там наш PAC: домены с `notion`
идут через туннель, всё остальное — напрямую. Поэтому Firefox не нужно ни
перезапускать с флагами, ни создавать отдельный профиль: `netsuite.ps1` при каждом
проходе проверяет и восстанавливает `AutoConfigURL`, если его сбросили.

Отдельный профиль или второй экземпляр браузера не используются специально — чтобы
не открывалось лишних окон и не ломались твои настройки.

## Из консоли

```powershell
powershell -ExecutionPolicy Bypass -File netsuite.ps1 -Action on
powershell -ExecutionPolicy Bypass -File netsuite.ps1 -Action status
powershell -ExecutionPolicy Bypass -File netsuite.ps1 -Action ensure
powershell -ExecutionPolicy Bypass -File netsuite.ps1 -Action restart
```

## Файлы

- `netsuite.ps1` — вся логика: `on` / `off` / `status` / `ensure` / `restart`
- `netsuite.json` — пути, имена процессов, порты. Пути записаны токенами
  (`%REPO%`, `%LOCALAPPDATA%`, `%DOCUMENTS%`) и разворачиваются в рантайме, поэтому
  файл ASCII и не зависит от кириллицы в профиле
- `setup.ps1` + `install.bat` — установка/починка одной кнопкой
- `on.bat`, `off.bat`, `status.bat`, `notion-window.bat` — то, на что смотрят ярлыки
- `autostart.vbs` — тихий `ensure` при входе в систему
- `shortcuts.ps1` — пересоздать ярлыки и автозагрузку (UTF-8 BOM: без него PowerShell 5.1
  не читает кириллицу в именах ярлыков)
- `bin\` — движки: `sing-box.exe`, `xray.exe`, `TgWsProxy_windows.exe`
- `notion\` — рантайм туннеля: `sb-config.json`, `pacsrv.ps1`, `boot.vbs`, `watch.ps1`,
  `build-tuic.ps1` (поиск новой ноды), `build.ps1` (VLESS-фолбэк), `collect.ps1`
- `logs\` — журналы

## Ограничения

- **zapret** требует администратора: его служба `zapret` создана установщиком
  `service.bat` в его собственной папке. Без админа пульт только проверяет, что
  `winws.exe` живой, и пишет предупреждение в лог.
- Бесплатная нода живёт не вечно. Задача `NotionTunnelKeepalive` раз в 10 минут
  проверяет туннель и при смерти ноды запускает поиск новой. Если ноды не нашлось,
  `sb-config.json` останется старый, и `ensure` будет пробовать снова.
- Все порты слушают только `127.0.0.1` — наружу ничего не светится.
- `sb-config.json` — конфиг бесплатной публичной ноды, ничего личного.
